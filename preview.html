2主要功能

Navi 是一个零第三方运行时依赖的导航站：后端只用 Node 内置模块，前端只用原生 JS 与 CSS，整体可直接丢进任意 Docker 环境。

🔌

服务发现（端口 → 卡片全自动）

自动识别正在运行的服务端口，按服务类型匹配图标，一键生成导航卡片。

  • Docker：读 Engine API 的容器端口映射（Unix Socket 优先，失败回退 TCP）
  • 本机：Linux 解析 /proc/net/tcp* 的 LISTEN 并反查进程名；Windows / macOS 降级 netstat / lsof
  • 内置 33 个服务指纹库，命中即自动配图标（未命中可在线探测）
  • 依赖容器（Redis / MySQL）与已停止容器默认不勾选，噪声进程自动过滤
🗂️

本地图床库（图标可复用）

卡片 Logo 有两条来源：在线图标库，或本地上传并沉淀进图床库长期复用。

  • 批量上传：多选或拖拽多张，前端按体积自动分片、显示进度
  • 逐张独立校验（文件头魔数），部分失败不影响其余图片
  • 库内可检索、可批量删除；被卡片引用的图片默认拒绝删除并列出引用方
  • 文件名按原始名 slug + 随机后缀命名，如 jellyfin-3f9a2b11.png
✏️

可视化编辑

点右上角「编辑」即进入编辑模式，所有改动先落到本地草稿，统一保存。

  • 分组与卡片的增 / 删 / 改、卡片拖拽排序
  • 保存时经服务端校验后写回 config.json，可随时取消
  • 支持粘贴导入 / 导出 JSON 配置
🌗

日 / 夜双主题

夜间为默认的「简约科技感」暗色主题，日间主题为浅色，两套配色由同一组 CSS 变量驱动，切换即时生效并记忆到本地。

🌐

内外网自动切换

每张卡片可同时配置外网地址与内网地址。访问时自动识别当前是否处于内网环境（localhost / 私有网段 / IPv6 本地地址），选中对应地址，也可手动一键切换。

🔍

搜索与快捷键

顶栏搜索框实时过滤站点（匹配名称与描述），按 / 快速聚焦，无结果时给出明确空状态提示。

🔐

访问密码保护

设置 NAVI_PASSWORD 即启用：登录页 + HMAC 会话 Cookie + 全站强制校验 + 登录限流 + 服务端登出吊销，未登录时所有接口返回 401。

💾

备份与恢复

一键导出带校验和的完整配置备份，导入时校验完整性并支持异常回滚；上传的图片实体随 data/uploads 一并持久化。

🐳

Docker 就绪 · IPv4/IPv6 双栈

默认监听 :: 双栈，官方镜像基于 Alpine，支持整目录数据挂载，规避单文件挂载在部分 NAS 上的 EBUSY / EXDEV 保存失败问题。

5接口与数据结构

后端共 15 个 HTTP 接口，全部基于 Node 内置模块实现。除登录与健康检查外均需认证。

接口方法用途是否写盘
/api/configGET / PUT读取与保存整站配置（分组、卡片）PUT 写 config.json
/api/discoverGET服务发现：返回识别到的容器 / 本机监听端口只读
/api/libraryGET列出本地图床库（含「被哪些卡片引用」）只读
/api/library/uploadPOST批量上传图标入库（逐张魔数校验）写上传目录
/api/library/deletePOST删除图片，带引用保护（409 + 引用清单）删文件
/api/uploadPOST单张 Logo 上传（同样入库，可复用）写上传目录
/api/backupGET导出带校验和的完整备份只读
/api/restorePOST导入备份（校验后写入，异常回滚）写 config.json
/api/login · /api/logoutPOST密码登录（签发 HMAC 会话）/ 服务端吊销登出无状态
/api/healthGET健康检查（含是否启用鉴权、版本号）只读
/uploads/<文件>GET图床图片访问（映射到上传目录，长效缓存）只读

🎨

图标解析规则

优先级：本地图床图片 → 在线图标 → 字母回退。icon 字段支持四种写法：

  • https://…png — 直接外链图片
  • jellyfin — Dashboard Icons（jsDelivr）
  • selfhst:portainer — selfh.st 图标库
  • iconify:simple-icons:github — Iconify 图标库

全部加载失败时回退为带渐变底色的首字母图标，不留破图。

🗃️

图床存储逻辑

不建数据库、不写索引文件——图床库目录直接由上传目录的文件系统推导，接口现算现返回。

  • 存储位置：NAVI_UPLOAD_DIR（Docker 为 /app/data/uploads）
  • 引用关系：item.logo = "/uploads/文件名"
  • 「使用中」与删除保护由服务端实时扫描配置计算，不额外持久化

6部署与预览方式

当前需求只需「能在浏览器打开预览」，因此本页是纯静态页；若要体验完整功能（含写盘、端口扫描、真实上传），按下面任一方式运行即可。

🖥️ 本机直接运行

● 推荐 · 功能最完整 
cd 项目目录
set PORT=8899
node server.js

零依赖，无需 npm install。启动后访问 http://localhost:8899；默认端口为 80。

🐳 Docker Compose

● 生产推荐 
docker compose up -d
# 数据整目录挂载在 ./data

想启用服务发现，需追加挂载 /var/run/docker.sock:ro（该 Socket 等同宿主机 root 权限，请仅在可信环境开启）。

📄 静态预览（本页）

● 当前正在使用 
直接双击 preview.html
或浏览器打开该文件

不依赖 Node 与网络，可用于快速展示界面与交互。此模式下无后端能力（不写盘、不扫端口）。

⚠️ 预览环境的两个已知限制：① 本机后台进程在会话结束后会被系统回收，因此 localhost 链接无法长期存活； ② 平台托管的云端实例虽链接稳定，但沙箱内没有 Docker Socket，服务发现会走降级路径并显示明确原因（这是设计行为，不是故障）。 若需要真实的服务发现效果，请在 Linux 主机或挂载了 Socket 的 Docker 中运行。

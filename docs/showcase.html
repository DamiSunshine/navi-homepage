P0 · 基础能力

先用起来最痛的四件事

搜索、打开、连通、备份 —— 这四项决定了这个站「好不好用」和「敢不敢用」。

P0-1

拼音搜索

读音记得、字忘了 —— 也能搜到

改动前只按标题与描述做子串匹配。记得住「家庭影院」但想不起字、手上只敲得出 jtyy 的时候，结果永远是空。

改动后支持中文子串、全拼（jiating）与首字母缩写（jtyy），且按拼音音节边界对齐——拼音串里的偶然字母组合不会误命中。

  • 20924 个常用汉字的拼音表（pinyin.js，465 行）首次搜索时才按需注入，不拖慢首屏。
  • 取不到拼音表时静默降级为纯子串匹配——功能缺失不等于报错。
  • 命中原因会显示出来（标题 / 全拼 / 首字母），不再是「莫名其妙出现在结果里」。

⌘K 命令面板

键盘一路走到底，还能顺手搜索

P0-3

卡片级内外网策略

在家走内网、在外走公网，且不阻塞点击

改动前一张卡只有一个地址。用域名在家访问要绕出去再绕回来；填了内网 IP 出门又打不开。

改动后全局三态（自动 / 只用内网 / 只用外网）+ 每张卡自己的 netMode；「自动」模式对每张卡片的内网地址做异步可达性探测。

  • 不阻塞点击：首帧先用启发式渲染，探测出结论后原地改写链接，用户感觉不到等待。
  • 探测结果逐卡缓存，不会每次刷新都重跑一轮。
  • 无法判断就如实说：HTTPS 页面探测 http://内网IP 会被浏览器混合内容策略拦掉，此时显式跳过判定并说明原因，不给假结论。
  • 写入口严格校验 netMode 取值——写成 "LAN" 会被拒绝，否则会静默退化成「自动」。

P1 · 内网与运维

NAS 上的真实处境：会断网、会采不到、会失效

这三项的共同点是降级必须是一等公民——拿不到数据不等于报错，更不等于假装拿到了。

P1-5

首页状态板

采不到就给 null，而不是 0

改动前首页没有运行状态。想知道「那台机器还活着吗」，得另外开一个面板。

改动后首页直接显示容器数 / CPU / 内存 / 磁盘水位（GET /api/status），全部带服务端缓存。

  • 降级是一等公民：采不到的项返回 null，从不返回 0——把「不知道」显示成「0%」是误导。
  • 整块取不到时静默隐藏并停止轮询，不在页面上挂一个永远转圈的错误块。
  • 后台标签页暂停轮询；容器视角的数字在未挂 docker.sock 时降级，其余功能照常。

P1-6

内置本地图标库

内网 / 断网不再是一排空框

改动前图标全部走公共 CDN。而这个站最典型的部署环境恰恰是没有外网的家庭内网——打开首页是一整页空框。

P1-7

服务发现的来源追踪与失效管理

只标记，绝不自动删除

改动前重新扫描时，源侧已经消失的卡片会被静默清掉——用户精心改过的标题、描述、图标一起消失，且没有任何提示。

改动后卡片记录来源（来自哪个容器 / 端口），源侧消失时只打上 stale 与「⚠ 可能失效」角标，绝不自动删除。

  • 两个显式动作交给用户：恢复全部、清理失效项（二次确认）。
  • 未接入的来源不做失效判定——Docker 没挂载时，不会把已有的发现卡片集体冤枉成「已失效」。
  • 只有 source.type === "discover" 参与判定，手工添加与导入的卡片永远不会被误标。
  • 失效标记字段严格校验（必须是布尔），写成字符串 "true" 会在写入口被拒。

P2

卡片标签 · 跨分组检索

类别记得、名字忘了

改动前搜索只能命中名称与描述，而且结果受分组限制——「下载类的站点到底散在哪几个组里」只能靠人翻。

改动后卡片可加可选 tags[]（最多 8 个、单个 12 字），搜索框与 ⌘K 面板都能按标签命中，命中不再受分组限制。

  • 与拼音搜索天然互补：拼音解决「读音记得、字忘了」，标签解决「类别记得、名字忘了」。
  • 卡片上的标签点一下就筛（跨分组）；标签本身也支持拼音——搜 xz 或 xiazai 都能命中「下载」。
  • 标签是人工整理的索引，所以随备份原样带走。
  • 后端校验字段形状：写成字符串会被直接拒——否则前端会把字符串遍历成单个汉字当标签，检索结果变得莫名其妙。

Bug Fixes

顺手修掉的 5 个真实缺陷

都不是「代码写得丑」，而是会真的伤到数据或线上产物的问题。前两个尤其值得单独说。

1

对外发布的首页截图被测试套件反复覆盖

修改前test/ui.test.cjs 顺手把正式发布图 ui-home.png 重截了一次——跟随系统偏好截成浅色，而预览页标注的是「夜间主题」。更糟的是跑一次回归就覆盖一次，并随发布包上线。
修改后删除该写者，并把「谁有权写哪张发布图」变成机器可查的清单：多一个写者、或新图没有生成脚本，回归直接红。截图只允许 test/page-shots.cjs 这一个生产者。
教训：测试的副作用不能外溢到发布产物。已加断言：发布截图清单可解析、引用图都存在、孤儿图集合与已知清单一致。
2

新增模块漏进 Dockerfile 的 COPY 清单

修改前本地测试全绿（测试直读源码目录），但镜像里缺文件，容器启动即 MODULE_NOT_FOUND——最讽刺的是「本地完美、上线全挂」。
修改后补上 COPY，并加断言：从 server.js 抽出全部 require("./x") 逐个核对镜像清单，缺一个就红。
护栏：test/imagecompose.test.cjs。动过模块清单就跑它。
3

弹窗过高，底部按钮点不到

修改前.modal 没有高度上限。字段一多（编辑弹窗新增「标签」后就到了临界点），弹窗向视口上下两端同时溢出，「保存 / 取消」被推到屏幕外，小屏笔记本根本点不到。
修改后封顶为 calc(100vh - 40px) 并改为弹窗内滚动。
这个问题是 UI 套件真实点击按钮时暴露的，肉眼看截图完全看不出来。
4

图床库「空库提示」偶发消失

修改前长期存在的「全量回归偶发 1 项失败、单独跑必过」。打开弹窗的一瞬间空状态区显示的是加载文案「正在读取图床库…」，断言没等它切到空状态就取值——机器稍忙就会失败，看起来像产品缺陷，实际是断言早于数据到达。
修改后改为等状态落定后再断言。这是那条「不稳定测试」的真正原因，已定位并修掉。
教训：不稳定测试要查到底，别用「单独跑能过」搪塞过去。
5

部署判定脚本在缺密码时「假装通过」

修改前scripts/check-deploy.cjs 在没提供密码的情况下会给出看似成功的结论，让人以为「线上已经是新代码」。
修改后如实标注「未验证」并说明如何补全，而不是假装通过。
判定口径：0=新 / 1=旧 / 2=判不了。判不了就说不确定。

零依赖的个人导航站 —— 模块职责、目录组织、调用关系与实现要点

仓库：mijunyi/navi-homepage ｜ 形态：零 npm 依赖的 Node HTTP 服务 + 原生前端
整理时间：2026-09-20 ｜ 依据：当前工作区代码实测（行数、导出、路由、依赖均取自源码，非估计）

4 个后端模块 零 package.json 19 个测试套件 / 940 项断言 amd64 + arm64 镜像

一、一句话定位

一个不依赖任何第三方包的轻量导航站：Node 内置模块直接起 HTTP 服务，前端是原生 HTML / CSS / JS，没有构建步骤——改完文件刷新即生效，容器镜像只多一份 node:22-alpine。 它面向的是「家里有 NAS / 一台小主机、想把自己的一堆服务收成一个主页」的场景，因此把 服务发现（自动识别容器与内网端口并生成卡片）、图床库（本地图标可重复选用）、 状态板（CPU / 内存 / 磁盘 / 容器数）和含图片的备份都做在了内置功能里。

四条工程红线

下面四条是这个项目反复被验证过、不接受任何单项收益去交换的约束，后续所有改动都要落在它们之内：

红线含义与代价
① 零 npm 依赖 + 零构建 运行时只有 Node 内置模块；仓库里没有 package.json。写 ZIP、拼音、图标库都自己实现。代价是要多写代码，收益是「十年后 clone 下来仍能跑」。
② 多架构镜像与冒烟 job 必须继续过 CI 里 amd64 + arm64 双架构构建与「启动容器请求健康接口」两个 job 是硬闸门，任何一个红都不算完成。
③ 断言只增不减 test/_baseline.txt 记录通过数与失败数，任何改动通过数只能 ≥ 记录值且失败必须为 0。文档里出现的每个数字都要有断言守着——否则它一定会烂掉（见第九节）。
④ 不挂 docker.sock 时全部功能可用 挂 socket 等于把宿主机 root 权限交给容器，所以它是可选的：未挂载时只有「容器视角」的状态板数字降级，其余功能（含服务发现退化为扫本机端口）照常工作。

五、数据模型

整个应用只有一份结构化数据：一个 JSON 配置 + 一个图片目录。没有数据库、没有 ORM。

{
  "site": {
    "title": "Navi", "subtitle": "个人导航站", "footer": "…",
    "defaultEngine": "百度",
    "searchEngines": [ { "name": "百度", "url": "https://www.baidu.com/s?wd=%s" } ]
  },
  "groups": [
    { "name": "开发工具",
      "items": [ { "title": "GitHub", "desc": "代码托管", "icon": "github-light",
                   "url": "https://github.com" }, … ] }
  ]
}

导航项（item）字段全表

字段类型必填说明与校验位置
titlestring✔卡片标题。后端拒绝空标题。
urlstring✔外网地址，后端强制 http(s):// 前缀。
descstring—副标题。空值不落库（保存时删除该键）。
lanUrlstring—内网地址，同样强制 http(s)://。
netModeenum—auto / lan / wan。写错会静默退化成自动，故在写入口明确拒绝（P0-3）。
iconstring—图标名。支持本地 slug、iconify:库:名、以及直接给 URL。
logostring—本地上传的图片路径（图床库或 /uploads/），优先级高于 icon。
tagsstring[]—标签（P2）。后端限制 ≤ 8 个、单个 ≤ 12 字、必须是非空字符串，与前端 normalizeTags() 同值——避免「前端存得进去、后端存不下」。
sourceobject—来源追踪（P1-7）：{ type: discover｜manual｜import, via, id, syncedAt }。只有 type==="discover" 参与失效判定，手工添加与导入的卡片永远不会被误标。
staleboolean—源侧已消失的标记（P1-7）。只写 true/false，写成字符串会在入口被拒。
staleAtstring—标记时间（ISO 字符串）。
为什么这些「可选字段」也要严格校验？因为它们的失败方式都是静默的： netMode:"LAN" 会退化成自动、stale:"true" 会让前端的布尔分支走错、 tags:"下载" 会让遍历字符串得到单个汉字当标签。 与其让用户看到「莫名其妙的行为」，不如在写入口直接给出可读的错误文案。

六、接口清单

共 15 条接口路由（13 个 /api/* 接口 + 登录页 /login.html， 其中 /api/config 有 GET / PUT 两个），另有 1 条静态资源兜底。 除下表中标注「公开」的 5 条外，其余全部经过同一个认证闸门（/api/ 前缀统一拦截，未认证返回 401）。

公开（无需认证）

路由方法说明
/api/healthGET健康检查。CI 的冒烟 job 靠它确认容器真的起来了。
/api/loginPOST密码登录（可配用户名），签发 HMAC 会话 Cookie；带登录限流。
/api/logoutPOST退出登录，服务端吊销会话。
/api/auth/statusGET查询认证状态与是否启用认证（前端据此显示/隐藏退出按钮）。
/login.htmlGET登录页；已认证时直接跳回首页。

需认证

路由方法说明
/api/configGET读取导航配置（SITE_TITLE / SITE_SUBTITLE 环境变量在读取时覆盖展示层）。
/api/configPUT写回配置：先 validateConfig 全量校验，再原子写（临时文件 + rename，跨挂载点失败时降级直写并报告）。
/api/backupGET导出备份。默认 JSON（仅配置）；?format=zip 时打包 config + 图床库图片 + 逐项 SHA-256。
/api/backup/restorePOST校验并恢复备份，自动识别 ZIP 与 JSON 两种格式。
/api/uploadPOST上传单张卡片 Logo（base64，落盘上传目录）。
/api/libraryGET列出本地图床库全部图片（含「被哪些卡片引用」）与在线图标预设。
/api/library/uploadPOST批量上传图标：逐张独立校验，允许部分成功，并回报每张的结果。
/api/library/deletePOST删除图床库图片，默认拒绝删除仍被卡片引用的图片。
/api/discoverGET服务发现：返回可直接生成卡片的候选条目 + stale 判定结果（checked / skipped）；不可用时返回明确原因而非空数组。
/api/statusGET状态板数据。?fresh=1 绕过服务端缓存（前端手动刷新走这条）。

七、关键调用链

下面六条链路覆盖了绝大部分代码，理解它们基本就理解了整个项目。

① 页面加载

浏览器 GET /  →  serveStatic → sendHtml
                 ├─ 把 HTML 里所有 .js/.css?v=… 统一替换成本次资源版本号
                 │    （版本号 = public/js + public/css 里的最新 mtime，带 3 秒内存缓存）
                 └─ HTML 本身 no-cache，js/css 强缓存 7 天
→ 加载 style.css / icon-map.js / app.js
→ app.js 启动：GET /api/config → render() 渲染分组与卡片
                 ├─ 逐卡异步探测内网可达性（结果缓存；混合内容场景直接放弃判定，不报错）
                 ├─ 图标解析：本地 227 表命中 → 否则 CDN → 再失败降为字母方块
                 └─ 状态板：GET /api/status，30 秒轮询；全部采不到就静默隐藏并停止轮询
→ 拼音表在这一刻不加载，等用户真的开始搜索才注入 pinyin.js

② 编辑并保存

点「编辑」→ 进入编辑模式（卡片可拖拽、出现保存栏）
→ 弹窗填字段 → 提交时前端收敛（去重 / 截断 / 空值不落库）
→ PUT /api/config  →  validateConfig() 全量校验（错误信息直接给用户看）
                   →  saveConfigAtomic() 临时文件 + rename
                      └─ 跨挂载点报 EBUSY/EXDEV/EPERM/EACCES 时降级为直写并如实回报 mode

③ 服务发现（本项目最复杂的一条）

GET /api/discover → discovery.discover()
   ├─ 列容器：Docker API（unix socket 或 TCP）→ 容器名 / 镜像 / 端口映射
   │     └─ 拿不到 socket → 不报错，改为「扫本机监听端口」并如实标注 via
   ├─ 本机端口：/proc/net/tcp（Linux）→ 失败则 netstat 兜底；带噪声进程过滤
   ├─ 指纹匹配：33 类常见自建服务的预设（名字 / 端口 / 关键词）→ 推断图标
   ├─ 地址构造：探测本机 IPv4 + LAN/WAN 基址 → 内外网地址各一份
   └─ computeStale()：只判「本次真的连上了的那些来源」
         ├─ 已消失 → 标记 stale + staleAt，绝不自动删卡片
         └─ 没连上的来源 → 记入 skipped，如实上报「本次没检查」
→ 前端「加入选中项」时写入 source={type:"discover", via, id, syncedAt}
→ 失效卡片在卡片上有角标、可「恢复」或显式「清理」（清理需二次确认）

④ 备份与恢复

GET /api/backup?format=zip → 打包含图片的备份

九、技术要点与关键取舍

下面这些是踩过坑之后定下来的规则，几条「看起来多余」的代码基本都对应这里的一行。

要点为什么这样做
浏览器能力缺失 ≠ 失败 局域网 HTTP 下没有 crypto.subtle。早期代码据此判定「备份被篡改」——把「无法判断」当成了「检测到问题」。现在的规则是：前端校验只是提前提示，后端才是权威；判不了就如实说判不了。
「检测不到」与「检测到坏了」必须分开 服务发现的失效判定只覆盖本次真的连上了的来源。否则「没挂 docker.sock」会被理解成「所有容器都没了」，一屏卡片全被标红。
前端版本号由 mtime 自动推导 js/css 走 7 天强缓存，缓存键是含 ?v= 的 URL。手工维护版本号必然会忘，表现为「代码改了、镜像也重建了，页面还是老行为」。现在服务端下发 HTML 时按整个前端目录的最新 mtime统一改写。
数据目录整目录挂载 单文件 bind mount 下写配置会跨挂载点 rename，在部分 NAS 上直接 EBUSY/EXDEV 保存失败。挂 ./data:/app/data 后 rename 发生在同一挂载点内，天然规避。
UI 测试真的去点按钮 卡片编辑弹窗加了一个字段后，弹窗超出视口，底部按钮在小屏笔记本上点不到——宽屏肉眼看不出，是 UI 套件真实点击时暴露的。同类：waitForSelector 默认等 visible，等一个本来就 hidden 的元素必然超时。
测试必须真自包含 卡片图标指向公共 CDN，而套件里带「全程无 JS 错误」断言——外部 CDN 抖一下就会被误判成代码有 Bug。lib/hermetic.cjs 把公网请求就地应答掉，但只放行 IP / localhost，因为内网地址正是被测功能本身。
文档里的数字必须有断言 曾经只有「总断言数」被守着，于是 docker-guide.html 里「各套件单独运行时的断言数」整批漂成了旧值而无人发现。规则：文档里出现的每个数字都要进 musts，旧数字要进 mustNots（否则防不住「把旧包发上线」）。
报告完成度要回到方案原文点数 曾经照着一行进度表的括号里列出的 5 项，就宣称「其余项全部落地」，而该阶段实际有 10 项。摘要本身就会漏项，统计口径必须来自原件。

十一、部署形态与数据安全

形态入口与要点
源码构建（默认）docker compose up -d（docker-compose.yml）。本机构建镜像，改完代码重建即生效。端口 8080:80，数据挂 ./data:/app/data。
拉取预构建镜像docker compose -f docker-compose.image.yml up -d。用 NAVI_IMAGE / NAVI_TAG 指定镜像源与版本（国内直连 ghcr.io 常不通，可换镜像站）。
裸 Node 运行node server.js。读 public/config.json 与 public/uploads，适合本地开发与预览。
数据安全只有一条要点：镜像＝程序（随时可重建），data/＝唯一不可再生的数据。 路径挂载由 Docker 之外的生命周期管理，所以 build / rm / --force-recreate / GUI「清除项目」都不会动它。 真正会丢的只有三种情况：① 手动删除；② docker compose down -v 或 volume rm（仅具名卷）；③ 迁移时漏拷贝。 升级前的标准动作是 tar czf backup.tar.gz -C <项目> data。 另注意：只有 GET /api/backup?format=zip 才含图片，默认 JSON 备份只含配置。
